# Домашнее задание: анализ данных и визуализация

Основной файл: [analysis_lab/data_analysis.ipynb](analysis_lab/data_analysis.ipynb).
В нём сохранены код, результаты выполнения, таблицы, диаграммы и выводы.
Дополнительные слои приложения не нужны: это последовательный анализ в одной тетрадке.

## Источник данных

[Тетрадка преподавателя](https://colab.research.google.com/drive/1wnP5RDyemAB2ATtckQvUnsOEVn20kbv_)
содержит ссылку на `bank_dataset.xlsx`, 10 000 клиентов и 16 столбцов.
JSON в предоставленной тетрадке отсутствует, поэтому решение сначала преобразует
Excel в JSON без очистки. Затем именно JSON загружается в файловую базу SQLite.
Это отличие от формулировки задания явно отмечено в тетрадке.
Источник скачивается автоматически; SHA-256 проверяет неизменность его содержимого.

## Соответствие пунктам задания

| Пункт | Реализация |
| --- | --- |
| Создать SQLite и загрузить JSON | Файл `bank_analysis.sqlite3`, таблица `clients_raw`, загрузка через `executemany` в транзакции |
| Выгрузить данные в pandas | Новое соединение, `pd.read_sql_query`, сверка с источником |
| Очистить дубликаты и выбросы | Полные дубли, проверка уникальности клиентов, IQR внутри каждого города |
| Рассчитать статистики | `count`, `mean`, `median`, `std`, `min`, `max` для числовых полей, кроме идентификатора |
| Построить столбиковую диаграмму | Число клиентов, средний баланс, средний доход и доля ушедших по городам |
| Сделать выводы | Шесть выводов, рассчитанных из данных, и сравнение оттока до и после фильтра |

SQLite не требует отдельного серверного процесса. Docker и предыдущие базы проекта
для этой работы не используются.

## Результаты

- Исходных строк: **10 000**. Полных дубликатов: **0**.
- Исключено по IQR: **449 строк (4,49%)**. Осталось **9 551**.
- Число клиентов после очистки: Ярославль — **4 786**, Ростов Великий — **2 404**, Рыбинск — **2 361**.
- Отток: Ростов Великий — **32,82%**, Рыбинск — **16,01%**, Ярославль — **15,86%**.
- Баланс неизвестен у **3 468** оставшихся клиентов (**36,31%**).
- Максимальное изменение оттока после фильтрации по городу — **0,66 п. п.** по модулю.

Пропуски баланса не заполняются средним: это сохраняет наблюдаемое распределение.
Для статистик баланса используется число известных значений, для остальных показателей —
все подходящие клиенты. IQR применяется к `score`, `age`, `balance`, `estimated_salary`,
но не к идентификаторам, бинарным признакам и дискретным счётчикам.
Статистические выбросы могут быть реальными наблюдениями; выводы описывают выборку
после выбранной фильтрации и не доказывают причины оттока.

## Как сдать через Google Colab

1. Откройте [Google Colab](https://colab.research.google.com/).
2. Выберите **Файл → Открыть блокнот → Загрузить** и загрузите `analysis_lab/data_analysis.ipynb`.
3. Сохраните копию на своём Google Диске, если это потребуется.
4. Выберите **Среда выполнения → Выполнить все**. Данные загрузятся автоматически.
5. Убедитесь, что видны таблицы, четыре диаграммы и выводы, а последняя кодовая ячейка
   сообщает об успешных проверках.
6. Через **Поделиться** предоставьте преподавателю доступ на чтение и скопируйте ссылку.
7. Прикрепите в LMS ссылку на свою выполненную тетрадку.

Ссылка преподавателя является источником, а не ссылкой на выполненную домашнюю работу.
Локальный `.ipynb` уже содержит результаты, но для сдачи нужна ваша копия в Colab.

## Локальный запуск

Из корня проекта, Python 3.9+:

```bash
source .venv/bin/activate
python -m pip install -r analysis_lab/requirements.txt
python analysis_lab/run_notebook.py
```

Скрипт запускает все ячейки и сохраняет результаты в исходную тетрадку только после
успешного выполнения. При первом запуске нужен интернет для получения данных.
Повторный запуск использует скачанный файл, проверяет его хеш и заменяет содержимое
учебных таблиц, поэтому строки не накапливаются.

В `analysis_lab/results/` появляются PNG диаграмм, CSV статистик, отчёт очистки,
границы IQR, исключённые строки с причинами и Markdown с выводами.
Исходные данные, SQLite и производные файлы исключены из Git: их создаёт тетрадка.
Графики и таблицы также встроены в `.ipynb` и доступны без запуска.

## Проверка решения

В тетрадке выполняются проверки сохранения данных при переходе Excel → JSON → SQLite → pandas,
уникальности клиентов, допустимости бинарных признаков, сохранения общего числа строк
между этапами и совпадения групповых показателей pandas с независимыми SQL-агрегациями.
